# 学校要求摄入工作流：把官方文件喂给 AI 生成硬约束规范

> 学校发的论文相关文件（要求通知、格式规范、撰写模板、评分标准、答辩安排）到手后，
> 先全部"喂"给 AI，合并生成一份 `school-requirements-spec.md` 硬约束规范，
> 之后所有写/改论文的动作都以它为准——不靠记忆、不靠"应该够"。

## 为什么需要这一步

用 AI 写论文时，学校要求是最容易被忽视的硬约束。靠记忆或每次翻原文档的坑：

- 学校要求散落在多个文件里（通知正文 + 附件模板 + 评分表 + 口头补充），漏看一个就可能返工
- AI 生成的内容不符合格式要求，定稿后才发现，返工成本极高
- 老师发新通知后，不知道哪些条目变了、哪些还作数

**一份单一权威规范文件 = 写/改论文、生成 Word、提交前自查全部以它为准。**

## 第一步：收集归档文件

把学校发的一切文件复制到论文项目的专用目录，保留原件不要修改：

```
thesis-project/
└── school-docs/              # 学校文件原件（只读归档）
    ├── 撰写模板.doc
    ├── 格式规范.pdf
    ├── 抽检评议要素.pdf
    ├── 论文工作通知.pdf
    └── 参考体例范文.pdf       # 如果学校给了样例论文
```

## 第二步：按格式读取文件内容

| 格式 | 工具 | 安装 |
|------|------|------|
| .pdf（有文字层） | `pymupdf`（fitz） | `pip3 install pymupdf` |
| .pdf（纯图片型） | pymupdf 提取图片 → 视觉模型读图 | 同上 |
| .doc（旧版 Word） | macOS `textutil` | 系统自带 |
| .docx | `python-docx` | `pip3 install python-docx` |
| .xlsx | `openpyxl` | `pip3 install openpyxl` |

```python
import fitz
doc = fitz.open("格式规范.pdf")
for page in doc:
    text = page.get_text()
    if not text.strip():          # 图片型PDF，text层为空
        for img_info in page.get_images():
            pix = fitz.Pixmap(doc, img_info[0])
            pix.save("/tmp/extracted.png")   # 再用视觉模型读图
```

macOS 读 .doc：`textutil -convert txt -stdout '撰写模板.doc'`

## 第三步：生成 school-requirements-spec.md

把提取出的全部内容喂给 AI，按下面的骨架生成规范。三条硬要求：

1. **原文优先** — 数字、字号、磅值、字数限制必须保留学校原文，不要转述（转述会引入误差）
2. **写成硬约束** — 用"必须/不得/≤/≥"的表述，AI 写作时才能机械执行，不是"建议"
3. **按主题分章** — 结构/字数/标题/图表/参考文献/评分/提交/答辩，各成一节便于后续局部更新

### 规范骨架模板

```markdown
# 本校毕业论文 — 学校官方要求规范
> 来源：学校发的全部官方文件，逐份提取后合并。
> 本文件是写/改论文的硬约束，不是建议。
> 生成日期：YYYY-MM-DD。学校发新通知时，先更新本文件再动笔。

## 一、论文结构（严格按此顺序，缺一不可）
| # | 组成部分 | 要求 |
（封面→声明→承诺书→摘要→目录→正文→结论→致谢→参考文献→附录→外文资料，
  每部分写明学校的具体要求）

## 二、字数硬指标
| 项目 | 要求 |
（正文/摘要/绪论/致谢/题目各自的字数限制）

## 三、层次与标题格式
（章/节各级的编号格式、对齐方式、空字符规则、标题禁忌）

## 四、图表公式规范
（编号规则、图题表题位置、字体字号、线条磅值、跨页规则）

## 五、参考文献格式
（标注方式+字号、各文献类型[J][M][D][EB/OL]等的格式模板+示例、数量要求）

## 六、语言与内容要求
（语体要求、术语解释、数字与量的单位规范）

## 七、评分/评审标准对照表
| 一级指标 | 分值 | 审查要点 |
（学校或省级抽检的评分维度，逐项写清怎么拿分）

## 八、定稿硬指标清单
（学校给的"必须达到"条目逐条列出）

## 九、格式检测标准
（检测平台+合格阈值，如万字差错率上限）

## 十、提交材料清单 + 答辩流程
（缺一不可的材料、命名规则、答辩环节时长与要求、PPT要求）

## 十一、参考体例范文的结构骨架
（如果学校给了样例论文，提取其目录结构作为可直接套用的章节骨架）
```

## 第四步：使用协议

1. **写/改论文前必须加载 spec** — 它是格式与内容的唯一权威，通用方法论与它冲突时以它为准
2. **提交前逐条对照** — 把老师通知拆成硬指标，逐条对照 Word 成品实测，输出对照表（要求|实测结果|状态），不凭"应该够"下结论
3. **学校发新通知时**：按本流程提取 → 更新 spec 对应章节 → 再动笔改论文
4. **spec 与通用方法论冲突时**：以 spec 为准（它是学校原文的直接提取）

## 实测坑

1. **图片型 PDF**：text 层为空不等于没内容，要用 `page.get_images()` 提取图片再读，别直接跳过
2. **WAF 保护的高校网站**：教育网站常有 JS 反爬，自动化访问返回空壳页面，需人工截图/复制原文
3. **行政表格不用读**：成绩汇总表、教师汇总表等是学校填写用的，跳过
4. **上传窗口期可能早于官方截止日**：老师通知里的时间范围优先于文件里的截止日期
5. **范文体例抄结构不抄内容** — 学校给的样例论文，借鉴的是章节骨架、摘要写法、格式细节，内容必须原创
6. **通知里的"建议"和"必须"要区分** — 评分标准里的"建议20张图表"和"缺一不可"的材料清单是两种约束力，spec 里要标注清楚
