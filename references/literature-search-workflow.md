# 文献检索与综述工作流：从知网检索到 GB/T 7714

> 毕业论文的文献环节有三道坎：**检索**（知网有反爬）、**筛选**（近三年占比等指标）、**格式化**（GB/T 7714）。
> 本工作流给出"手动兜底 + MCP 自动化"两条检索路径，以及配套的综述写法要求。

---

## 一、先明确硬指标（以学校 spec 为准）

- 参考文献总数 ≥ 35 篇（常见要求）
- 外文文献 ≥ 4-5 篇
- **近三年文献占比 ≥ 80%** —— 最容易不达标的一条，检索时就要有意识地控年份
- 文中要呈现：国内外研究现状 + 理论基础 + 技术路线图

> 如果你已经按 `school-requirements-workflow.md` 生成了学校硬约束规范，这些数字以规范里的原文为准。

---

## 二、路径 A：知网手动检索（兜底，永远可用）

知网对自动化访问有 IP 级反爬封锁，手动检索是最稳的方式：

1. 高级检索 → 学位论文/学术期刊 → 关键词组合（技术词 + 场景词，如"智能问答 + 高校"）
2. 筛选年份：限定近三年
3. 把检索结果（题名/作者/期刊/年份/卷期页）发给 AI，整理成 GB/T 7714 格式
4. 英文文献用 Google Scholar / 学校图书馆数据库，出版信息相对可靠

---

## 三、路径 B：知网 MCP 自动化检索（效率路线）

社区已有开源的知网 MCP 服务（如 [PluginsX/Cnki-Mcp](https://github.com/PluginsX/Cnki-Mcp)），接入后 AI 可以直接调用知网检索，不用人肉复制粘贴。

### 接入步骤

```bash
# 1. 安装（以 Cnki-Mcp 为例）
git clone https://github.com/PluginsX/Cnki-Mcp.git
cd Cnki-Mcp && pip install -e .
playwright install chromium   # 依赖浏览器内核模拟真实访问
```

```json
// 2. 在 MCP 配置（.mcp.json / IDE 的 mcp.json）中注册
{
  "mcpServers": {
    "CNKI": {
      "command": "python",
      "args": ["-m", "cnki_mcp.server"]
    }
  }
}
```

### 可用工具

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `cnki_search` | 文献检索 | `keyword`（必填）、`search_type`（SU主题/TI篇名/AU作者/KY关键词/AB摘要/FT全文）、`db_code`（CJFD期刊/CDMD博士/CMFD硕士）、`page_size`（1-50） |
| `cnki_get_paper_detail` | 单篇详情 | `paper_url`（必填） |

### 推荐用法

```
你：用 CNKI 工具检索"大语言模型 智能问答"近三年硕士论文，每个方向挑 5 篇
AI：（调用 cnki_search）→ 输出结构化清单
你：把这 15 篇整理成 GB/T 7714 格式，标注哪些需要我去核实卷期页
```

### 注意事项

1. **自动化≠无限制**：频繁检索仍可能触发验证码/封 IP，控制频率，被风控时退回路径 A
2. **MCP 配置含本地路径/Token 时，不要提交进 Git**
3. 中文文献的卷期页信息**必须以知网页面为准**，AI 可能编造，提交前抽查核实

---

## 四、文献综述写法（比检索更容易翻车）

检索到文献只是开始，综述写法决定深度分：

**❌ 罗列式（会被认为深度不够）：**
> 张三提出了 X 方法。李四提出了 Y 方法。王五提出了 Z 方法。

**✅ 每个方向必须包含三要素：**
1. **代表性工作** — 列举 2-3 篇
2. **对比分析** — 不同方案的优劣、适用场景
3. **选型理由** — 本系统为什么选 A 不选 B（这是把综述和你的论文绑起来的关键句）

---

## 五、进阶生态：从毕业论文到学术研究

如果后续还要发期刊/会议论文（不只是毕业论文），可以看学术研究全流程的技能库 [claude-scholar](https://github.com/Galaxy-Dawn/claude-scholar)（40+ 学术技能）。与毕业论文场景最相关的几个：

| 技能 | 用途 |
|------|------|
| `citation-verification` | 引用文献真实性核实（防止 AI 编造文献） |
| `paper-self-review` | 投稿/提交前的结构化自查 |
| `writing-anti-ai` | 学术写作降 AI 味（与本仓库第四章互补） |
| `doc-coauthoring` | 多人/多 AI 协同写作的规范 |
| `zotero-obsidian-bridge` | 文献管理工具链（Zotero + Obsidian） |

毕业论文阶段用本仓库的方法论 + 脚本即可；进入学术研究阶段再按需引入。
